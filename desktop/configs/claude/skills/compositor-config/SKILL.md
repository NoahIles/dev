# Compositor Config

Noah runs two compositors from the greeter: **niri** and **umbriel**. Every
config change lands in **both**, so switching sessions never loses a feature.
Parity is the contract: a change is done only when both sides carry it, or
the side that can't carries a comment saying why.

## Where things live

Both are live-lane dotfiles: `~/.config/<compositor>` symlinks into the repo,
so saved edits apply without a rebuild.

| | niri | umbriel |
|---|---|---|
| Repo dir | `~/nixos/desktop/configs/niri/` | `~/nixos/desktop/configs/umbriel/` |
| Rules | `rules.kdl` | `rules.toml` |
| Keybinds | `keybinds.kdl` | `keybinds.toml` |
| Zen/game mode | `game_mode.kdl` | `game_mode.toml` |
| Everything else | `config.kdl`, `layout.kdl`, `theme.kdl` | `config.toml` |
| Layout notes | `configs/niri/CLAUDE.md` | header of `config.toml` |
| Docs | https://github.com/YaLTeR/niri/wiki (pages named `Configuration:-<Topic>`) | https://docs.noctalia.dev/umbriel/<topic>/ |
| Valid keys | the wiki page | `umbriel config schema --json` |
| Validate | `niri validate` | `umbriel config validate` |
| Inspect windows | `niri msg -j windows` | `umbriel windows` |
| Inspect layers | `niri msg layers` | `umbriel layers` |

`noctalia.kdl` is generated by the Noctalia settings UI: put niri overrides
in `theme.kdl` instead.

## Steps

1. **Read both sides.** Find the existing niri and umbriel config for the
   feature. Umbriel files are ports of the niri ones and carry
   `# niri: <equivalent>` comments; follow those to the matching block. Done
   when you can name the block (or the gap) on each side.
2. **Fetch the docs for both.** Open the niri wiki page and the umbriel docs
   page for the topic, and check umbriel key names with
   `umbriel config schema --json | jq -r '.. | objects | .path? // empty' | grep <section>`.
   Both projects rename options between releases; the docs and schema win
   over memory and over this skill.
3. **Get the window identity** when writing a rule: app-id and title from the
   inspect commands above. Match on app-id; add title only to split one app's
   windows (main vs pop-out).
4. **Edit both files**, placing the new block at the same position in each,
   with the same comment explaining *why* the rule exists. Rule order
   matters in both: every matching rule applies and later rules win for the
   same key.
5. **Record any gap.** When one compositor has no equivalent, leave a comment
   at the matching spot in the other file: `# niri-only: <what and why>` or
   `// umbriel-only: <what and why>`.
6. **Validate both**: `niri validate` and `umbriel config validate`, each
   passing. Then apply to the running session: umbriel hot-reloads on save
   (confirm with `journalctl --user -u umbriel.service --since -2min | grep
   config`); niri reloads on save too, or force it with
   `niri msg action load-config-file`. Only the running compositor's IPC
   works.

## Translating niri ↔ umbriel

| niri (KDL) | umbriel (TOML) |
|---|---|
| `window-rule { ... }` | `[[window_rule]]` |
| several `match` lines (OR) | array on one selector, `match.app_id = ["a", "b"]` (OR); OR across *different* selectors needs separate rules |
| `match app-id=X title=Y` (AND) | `match.app_id = X` plus `match.title = Y` (selectors AND) |
| `exclude title=X` | negative lookahead: `match.title = "^(?!X)"` |
| `open-floating true` | `default_floating = true` |
| `open-focused false` | `default_focused = false` |
| `open-fullscreen true` | `default_fullscreen = true` |
| `open-on-output "Name"` | `default_output = "Name"` |
| `default-column-width { proportion 0.33; }` | `default_scrolling_extent = 0.33` |
| floating `default-column-width` + `default-window-height` | `default_floating_size = { width, height }` (fractions) or `default_floating_size_px` |
| `default-floating-position x= y= relative-to="top-right"` | `default_position = { x, y, anchor = "top_right" }` |
| `variable-refresh-rate true` | `vrr = "always"` |
| `opacity 0.95` | `opacity = 0.95` |
| `background-effect { blur false }` | `blur = false` |
| `geometry-corner-radius` | `corner_radius` |
| `block-out-from "screen-capture"` | `block_capture` |
| `layer-rule` + `match namespace=` | `[[layer_rule]]` + `match.namespace` |
| `prefer-no-csd` | `[appearance] prefer_no_csd = true` |

Escaping: KDL raw strings `r#"^com\.foo$"#` take single backslashes; TOML
basic strings double them, `"^com\\.foo$"`, or use a literal string
`'^com\.foo$'`.

## Gotchas

- **niri `match` lines are OR'd**: multiple `match` lines in one block match
  any of them, not all. Conditions inside one `match` line are AND'd.
- **niri `gaps` is layout-only**, not a window-rule property. Use
  `open-maximized-to-edges true` (umbriel: `default_maximize_to_edges`) to
  strip gaps/borders/struts for one window.
- **Opening vs dynamic properties**: niri `open-*` and umbriel `default_*`
  apply once when the window opens; everything else (opacity, blur, borders)
  applies continuously. Close and reopen the window to test an opening rule.
- **Umbriel floats dialogs by default** and exposes `match.is_dialog`
  (window has a parent); niri has neither, so niri pop-out rules match by
  app-id plus title.
- **Umbriel layer rules only carry blur keys**; niri layer-rule `opacity`,
  `shadow`, etc. are niri-only.
- **Running `umbriel` with no subcommand starts a nested compositor.** Use a
  subcommand from `umbriel help`.
