# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Noah's dotfiles for the [niri](https://github.com/YaLTeR/niri) Wayland scrollable-tiling compositor, paired with the Noctalia shell (bar/dock/launcher/panels, driven via `noctalia msg ...`). Config is written in [KDL](https://kdl.dev). Not a git repo.

## Commands

- Validate config after any edit: `niri validate`
- Reload a running session after editing: `niri msg action load-config-file`
- Inspect the focused window (app-id/title, used to write window-rule matchers): run the `Mod+Alt+I` bind, or directly: `niri msg --json focused-window`
- List outputs (for output blocks in `config.kdl`): `niri msg outputs`

There is no build/lint/test suite — validation is `niri validate`, and the real test is reloading and observing the compositor.

## File structure and load order

`config.kdl` is niri's actual entrypoint (what niri itself loads). It holds input/output/animation settings and ends with `include "./niri.kdl"`. `niri.kdl` is a second-level includes hub that pulls in everything else, in this order:

```
config.kdl
├─ input, output, animations, hotkey-overlay, screenshot-path  (inline)
└─ include "./niri.kdl"
   ├─ include "./exec.kdl"       — spawn-at-startup commands
   ├─ include "./rules.kdl"      — window-rule / layer-rule / debug blocks
   ├─ include "./layout.kdl"     — gaps, focus-ring, border, shadow, struts
   ├─ include "./noctalia.kdl"   — AUTOGENERATED by Noctalia settings UI — don't hand-edit
   ├─ include "./theme.kdl"      — manual overrides applied after noctalia.kdl (colors win by load order)
   └─ include "./keybinds.kdl"   — all custom binds (280 lines)
   (include "./game_mode.kdl" is commented out by default — toggled by niri-zen-toggle)
```

Because later includes override earlier ones for the same KDL node, color/layout overrides belong in `theme.kdl`, not `layout.kdl` or `noctalia.kdl`.

`noctalia.kdl` is regenerated by the Noctalia settings app — treat it as generated output, not something to edit by hand. Put manual tweaks (e.g. gradient overrides) in `theme.kdl` instead, since it's included after and wins.

## scripts/

Standalone bash/nushell scripts invoked from `keybinds.kdl` via `spawn`, using `niri msg` / `noctalia msg` for compositor and shell IPC:

- `niri-window-info` — shows focused window's app-id/title in a notification and copies ready-to-paste `window-rule match` strings (regex-escaped, anchored) to the clipboard — the fast path for writing a new rule in `rules.kdl`.
- `niri-zen-toggle` — "zen mode": sed-toggles the `include "./game_mode.kdl"` line in `niri.kdl` on/off, reloads config, and shows/hides the Noctalia bar+dock. State tracked via `/tmp/niri-zen-mode` sentinel file.
- `niri-manage-outputs` / `niri-manage-outputs.nu` — output enable/disable management (same script, bash and nushell variants).

## Conventions in this config

- Window rules in `rules.kdl` match by `app-id` (regex, raw KDL strings `r#"..."#`) and sometimes `title`. Comment above each rule explains *why* the rule exists (e.g. the xglx-spike and WezTerm rules document specific upstream quirks being worked around) — keep that pattern when adding rules.
- `.claude/settings.json` allowlists read-only/diagnostic commands (`niri validate`, `systemctl status`, `journalctl -k`, etc.) for this project — extend it rather than approving destructive commands ad hoc.
- The `niri-config` skill is the preferred path for config edits: it fetches current niri wiki docs before changing anything and runs `niri validate` after every edit. Use it for window rules, keybindings, layout, or layer rules instead of editing KDL from memory.
- The `niri-scripts` skill covers writing/editing anything in `scripts/` that talks to niri or Noctalia IPC.
